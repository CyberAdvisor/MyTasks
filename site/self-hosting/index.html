Your own copy

My Tasks is open source under the MIT licence, so you can host your own copy, change it, or both. This page is for people comfortable with GitHub and a little code. To simply use My Tasks, you don't need any of this: see the Guide.

Before you start

  • A free GitHub account. Your copy is a fork of the My Tasks repository, published by GitHub Pages at no cost.
  • Your copy needs an address of its own, served from its root: your own domain or subdomain (such as tasks.example.com), or yourname.github.io. An address with a folder, such as yourname.github.io/MyTasks/, doesn't work, because the website and app link to each other from the root.
  • Choose the address once. Each device keeps its copy of your tasks under the address, so a new address starts empty on every device.
  • Your tasks stay in your own gist, whichever copy you use. A device that opens your copy for the first time is set up like a new device: connect it to your existing gist with your token and passphrase, as in Add another device.
  • A copy you host is yours to look after. Problems with it go to you, not to My Tasks.

Host it unchanged

  1. Sign in to GitHub, open the My Tasks repository and click Fork, then Create fork. To use yourname.github.io as the address, name the fork yourname.github.io (with your own GitHub name).
  2. In your fork, open the Actions tab and click the button that turns workflows on. GitHub turns them off in a new fork.
  3. Open Settings › Pages. Under Build and deployment, set Source to GitHub Actions.
  4. For your own domain: enter it under Custom domain on the same page, click Save, and point the domain at GitHub Pages as GitHub explains. Then tick Enforce HTTPS when it's offered. My Tasks needs HTTPS to install and to encrypt.
  5. In your fork, change site/CNAME to your domain, or delete it if you use yourname.github.io. Committing the change to main starts the first deploy.
  6. When the Actions tab shows the run finished, open your address. The app is at /app/.

Every push to main runs the tests, then publishes the website and app. If a test fails, nothing is published, and the run in the Actions tab shows why.

Change it

You need Node 20 or later and git. Clone your fork, then in its folder:

  1. npm install, once.
  2. npm run dev runs the app on your computer at http://localhost:5173/app/, and reloads as you edit.
  3. npm test runs the unit tests, and npm run test:ui the interface tests in real browsers (the first time, run npx playwright install chromium webkit).
  4. Commit and push to main to publish your change.

The app is written in Svelte and TypeScript; the website is plain HTML in site/. DEVELOPMENT.md in the repository is the map of the code. In a copy at another address, also change:

  • WEBSITE in src/lib/website.ts: where the app's help links go.
  • The GitHub links in the website's shared footer, and the Report an issue link on the Limitations page, so they point at your fork.

A change to how tasks are stored or synced can make a gist unreadable to other copies, including mytasks.fyi. If you use one gist with several copies, keep them on the same version.

Get later updates

When My Tasks changes, your fork's page on GitHub shows that it is behind. Click Sync fork, then Update branch: that pushes to main, which publishes the update. If your changes touch the same lines, GitHub asks you to settle the difference first. The Roadmap shows what's coming.

Other hosts

Any host that serves static files works, as long as the copy is at the root of its address and served over HTTPS. Run npm run build, then publish the dist/ folder, which holds the website with the app in dist/app/.
