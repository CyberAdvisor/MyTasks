Security

Last updated November 12, 2026

How My Tasks protects your list, and what it can't protect against. The code is open source, so you can check it yourself.

Encryption

  • Your list is encrypted on your device before it is sent to your gist, using the browser's built-in Web Crypto.
  • The key is derived from your passphrase with PBKDF2-SHA-256, 600,000 rounds and a random 16-byte salt.
  • The list is encrypted with AES-256-GCM, with a fresh 12-byte IV every time it's saved. GCM also detects any change to the encrypted file.
  • Each device asks for your passphrase once and keeps the key in a form the browser won't let any script read out. The passphrase itself is never stored or sent anywhere.
  • Change Passphrase re-encrypts your gist with a new salt. Your other devices then ask for the new passphrase.

Your GitHub token

  • My Tasks uses a classic personal access token with only the gist permission. That permission covers all of your gists, not only My Tasks'.
  • Each device keeps its token in the browser's storage, unencrypted, and uses it only with GitHub's API.
  • If a device is lost, revoke its token at github.com/settings/tokens.

The app and this website

  • Both are static files served over HTTPS by GitHub Pages. There is no My Tasks server.
  • A strict Content Security Policy lets the app run only its own scripts, never eval, and connect only to itself and GitHub's gist API. This website may not connect anywhere.
  • Notes are always shown as plain text, never as HTML, so pasted text can't run in the app.

What it can't protect against

  • Anyone who can use your unlocked device: each device's working copy is not encrypted.
  • Anyone who has both your token and your passphrase.
  • Malicious browser extensions, or malware on your device.
  • Someone with access to your GitHub account deleting your gist. They can't read it without your passphrase.
  • A forgotten passphrase: if no device is still connected, your data is lost.

Reporting a vulnerability

Please report security problems privately, through GitHub's private vulnerability reporting, not in a public issue. Include what you found and how to reproduce it.
